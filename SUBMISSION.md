## Исправления

- Некорректный тип `sslmode` в TOML теперь вызывает понятную ошибку конфигурации вместо необработанного `TypeError`.
- Проверка БД завершается ошибкой при неверной версии PostgreSQL, локали, кодировке, формате пароля, правилах аутентификации или правах роли. Ранее скрипт только выводил значения.
- Добавлены отдельные интеграционные тесты настоящего клиента: успешный запрос, неверный пароль и попытка добавить опции в логин. Подменяется только ввод пользователя; драйвер и соединение настоящие.
- `verify.ps1` объединяет проверку БД, модульные и интеграционные тесты, не печатает пароль и восстанавливает прежнее окружение процесса.
- `setup.ps1` повторно использует готовое окружение, допускает явный путь к Python и поддерживает `-DependenciesOnly`. Зафиксированы установленные версии зависимостей.
- `.gitattributes` сохраняет LF в shell-скриптах при клонировании на Windows.

## Как завершить запуск на этом компьютере

WSL требует системной установки с правами администратора и может потребовать перезагрузки. Доступ к папкам установки Docker Desktop в текущей среде не предоставлен, поэтому системная установка не выполнялась.

1. Откройте PowerShell **от имени администратора** и выполните:

   ```powershell
   wsl --install --no-distribution
   ```

   Если Windows потребует перезагрузку, сохраните работу и перезагрузите компьютер. Затем проверьте `wsl --version`.

2. Установите [Docker Desktop с официального сайта](https://docs.docker.com/desktop/setup/install/windows-install/), запустите его и дождитесь готовности движка Linux-контейнеров. При первом запуске потребуется принять условия Docker.

3. В обычном PowerShell перейдите в папку проекта и выполните:

   ```powershell
   .\setup.ps1
   ```

   Локальное окружение `.venv` и `.env` уже подготовлены. В свежей копии из архива `setup.ps1` создаст их заново; потребуется установленный Python 3.11+. Если запуск скриптов запрещён только стандартной политикой личного PowerShell, допустим однократный запуск `powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1`. Политики организации не обходите.

4. Убедитесь, что `setup.ps1` завершился сообщением `READY`, затем выполните:

   ```powershell
   .\verify.ps1
   .\run.ps1
   ```

   Логин: `seminar_user`. Пароль: значение `APP_DB_PASSWORD` из локального `.env`. Не показывайте `.env` на скриншотах и не отправляйте его в публичный репозиторий. Успешный клиент должен вывести версию PostgreSQL 18, пользователя `seminar_user` и базу `seminar_db`.

Справка: [установка WSL](https://learn.microsoft.com/en-us/windows/wsl/install), [параметры команды WSL](https://learn.microsoft.com/en-us/windows/wsl/basic-commands), [установка Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/).

## Что показать преподавателю

1. Публичную ссылку на Git-репозиторий с кодом, конфигурацией, Dockerfile и тестами.
2. `docker compose ps` со здоровым контейнером.
3. Успешный вывод `.\verify.ps1`: проверки БД, 11 модульных и 3 интеграционных теста.
4. Интерактивный запуск `.\run.ps1` и результат `SELECT VERSION();`.
5. Отказ при логине `seminar_user host=other.example` без смены адреса сервера.

Настройки сервера хранятся в `config.toml`, логин и пароль передаются отдельными именованными аргументами `psycopg.connect`. Для базы используется право `CONNECT`, а `USAGE` относится к схеме `public`. Ответы на вопросы защиты приведены в README.

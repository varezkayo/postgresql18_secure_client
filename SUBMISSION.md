# Отчёт о проверке приложения PostgreSQL

Дата проверки: 22 октября 2026 года.

Цель работы — запустить PostgreSQL 18 в Docker и реализовать консольный клиент, который читает настройки сервера из файла, запрашивает логин и пароль и выполняет `SELECT VERSION();`. Ввод учётных данных не должен позволять добавлять параметры подключения.

## Окружение

- Windows, Docker Desktop с Linux-контейнерами и WSL 2.
- PostgreSQL 18.6 на базе Debian Bookworm.
- Python 3.12.14 и `psycopg` 3.3.6.
- База `seminar_db`, кодировка UTF8, локаль `ru_RU.UTF-8`.
- Роль `seminar_user` с правом `CONNECT` к базе и `USAGE` к схеме `public`.
- Порт сервера опубликован как `127.0.0.1:5432`.

## Реализация

`Dockerfile` устанавливает русскую локаль и добавляет конфигурацию PostgreSQL. `compose.yaml` описывает контейнер, переменные окружения, проверку готовности сервера и том для данных.

При первой инициализации БД скрипт `docker/01-create-role.sh` создаёт роль приложения и выдаёт права. Для новых паролей и правил аутентификации настроен SCRAM-SHA-256.

Клиент `src/app.py` читает `config.toml`, проверяет допустимые ключи и типы значений, запрашивает логин через `input()` и пароль через `getpass.getpass()`. Затем открывает соединение через `psycopg.connect(**params)`, выполняет запрос версии, получает имя текущего пользователя и базы и выводит результат. Соединение и курсор закрываются при выходе из блоков `with`.

## Защита подключения

Настройки сервера и введённые учётные данные передаются отдельными именованными аргументами. Например, логин `seminar_user host=other.example` остаётся целиком значением `user`; он не меняет адрес сервера. В конфигурации допускаются только `host`, `port`, `dbname`, `connect_timeout` и `sslmode`.

Пароль не записывается в `config.toml` и не выводится приложением. Локальный `.env` используется для создания учётных данных контейнера и для интеграционных проверок; при обычном запуске клиент получает пароль из ввода. `.env` исключён из Git и архива исходников.

В локальном стенде используется `sslmode=disable`. SCRAM защищает аутентификацию, но не заменяет шифрование SQL-трафика. Для удалённого подключения требуется отдельно настроить TLS и проверку сертификата.

## Результаты

| Проверка | Результат |
|---|---|
| Сборка Docker-образа и запуск контейнера | Успешно |
| Версия PostgreSQL | 18.6 |
| Кодировка и локаль БД | UTF8, `ru_RU.UTF-8` |
| Пароль роли и правила аутентификации | SCRAM-SHA-256 |
| Права `CONNECT` и `USAGE` | Подтверждены |
| Модульные тесты | 11 из 11 |
| Интеграционные тесты с настоящей БД | 3 из 3 |
| Интерактивный вход и `SELECT VERSION();` | Успешно |

Модульные тесты проверяют конфигурацию, обработку ввода и сохранение параметров подключения. Интеграционные тесты проверяют успешное подключение приложения, отказ при неверном пароле и отказ при попытке добавить опции в логин.

Проверки выполнены локально на Windows и в GitHub Actions. Автоматическая проверка БД завершается с ошибкой при несоответствии версии, локали, кодировки, SCRAM, правил доступа или прав роли.
